# ADR-0001: Backend форм: PHP, сменяемый почтовый адаптер, SQLite с ретеншеном, без админки

| Поле | Значение |
|---|---|
| Статус | **proposed** (переходит в `accepted` вместе с spec WEB-2026) |
| Дата | 2026-10-02 |
| Владелец решения | владелец проекта |
| Связи | [intent](../changes/WEB-2026/intent.md) · [spec §5–§6](../changes/WEB-2026/spec.md) · [plan P-07](../changes/WEB-2026/plan.md) |

## Контекст
- На сайте три формы: `kontakt` (страница Kontakt), `kurz` (Kurzanfrage на главной), `widerruf` (Vertrag widerrufen).
- Сейчас их обрабатывает `kontakt.php` (PHP 8, `mail()`, honeypot, минимальное время заполнения, JSON- или redirect-ответ,
  Eingangsbestätigung для Widerruf, тестовый режим `KONTAKT_TEST=1` → `kontakt-test.log`). Заявки нигде не хранятся.
- Хостинг заказчика неизвестен. Владелец выбрал вариант «PHP + сменяемый адаптер»: деплой в задачу не входит.
- Владелец выбрал вариант «формы + хранение заявок, без логина». Срок хранения — 90 дней, настраивается.
- В среде нет composer, поэтому runtime-зависимостей быть не должно. Есть PHP 8.5 с `pdo_sqlite`, `openssl`, `mbstring`.
- Локальный превью сейчас запускается через `python3 -m http.server` и PHP не исполняет.

## Варианты
1. **Оставить как есть** (`mail()`, без хранения). Минимум работы, но не выполнено решение о хранении, письма теряются
   при сбое `mail()`, а на хостинге без `mail()` формы не работают.
2. **PHP + адаптеры + SQLite, без админки** (выбран). Сохраняет стек и URL, работает на любом PHP-хостинге,
   письма можно слать через SMTP хостера, копия заявки защищает от потери письма.
3. **Node/Express или Cloudflare Worker.** Нужен другой хостинг, внешний почтовый сервис или аккаунт и новые зависимости.
   Противоречит решению владельца и неизвестному хостингу.
4. **PHP + админка с логином.** Появляются auth и хранилище PII с доступом через веб, то есть профиль «высокий риск».
   Владелец этот вариант отклонил.

## Решение
1. **Endpoint**: `POST /kontakt.php`. URL сохраняется, файл остаётся тонкой точкой входа и подключает код из `server/` (новый каталог).
2. **Структура (новые файлы):**
   - `server/bootstrap.php`: загрузка конфигурации, автозагрузка классов, обработка ошибок без вывода деталей.
   - `server/config.example.php` → копия `server/config.local.php` (в `.gitignore`). Ключи: `RECIPIENT`, `FROM_ADDRESS`,
     `MAIL_TRANSPORT` (`log|mail|smtp`), `SMTP_HOST/PORT/USER/PASS/SECURE` (`tls|ssl|none`), `STORAGE_PATH`,
     `RETENTION_DAYS=90`, `RATE_LIMIT` (по умолчанию 5 отправок за 10 минут), `MIN_FILL_SECONDS=3`, `ALLOWED_ORIGINS`.
     Переменные окружения имеют приоритет над файлом. Без конфигурации действуют безопасные значения по умолчанию: `log` и путь внутри `storage/`.
   - `server/lib/Validator.php`: правила и немецкие тексты ошибок (единый список для сервера; клиент берёт те же тексты из `build.py`).
   - `server/lib/Mailer.php` (интерфейс) + `LogMailer` (пишет в `storage/mail.log`), `MailFunctionMailer` (`mail()`),
     `SmtpMailer`: нативный SMTP-клиент на `stream_socket_client` с STARTTLS/SSL и `AUTH LOGIN`, без сторонних библиотек.
   - `server/lib/SubmissionStore.php`: PDO SQLite. Таблица `submissions(id, created_at, form, name, email, phone, service,
     message, order_no, items, consent_at, mail_status)` и таблица `rate_limit(key_hash, window_start, count)`.
     Схема создаётся при первом обращении (`CREATE TABLE IF NOT EXISTS`).
   - `server/lib/RateLimiter.php`: ключ `sha256(IP + суточная соль)`, где соль генерируется и хранится в БД и меняется каждые сутки.
     Сырой IP не сохраняется, записи лимита живут не дольше 24 часов.
   - `server/bin/submissions.php` (CLI): `list [--days N]`, `export --format csv|json`, `purge`. Через веб недоступен.
   - `server/router.php`: роутер встроенного сервера `php -S` для локальной работы. Отдаёт статику, исполняет `kontakt.php`,
     отвечает 404 через `/404.html` и закрывает пути из AC-10.
3. **Порядок обработки**: метод POST → проверка Origin/Referer (тот же хост или `ALLOWED_ORIGINS`) → honeypot `website`
   (тихий успех) → минимальное время `t` (тихий успех) → rate limit (429) → нормализация и валидация (422) → запись в SQLite
   → отправка письма владельцу → для `widerruf` письмо-подтверждение отправителю → `mail_status` в БД → ответ.
   Если письмо не ушло, заявка всё равно сохранена. Пользователю показывается ошибка с телефоном
   `0381 25 22 39 41`, в журнал пишется статус без персональных данных.
4. **Ответы**: при `Accept: application/json` или `X-Requested-With: fetch` возвращается JSON `{ok, errors{field:msg}, error}`.
   Без JS: успех даёт 303 на `/kontakt/danke/` (для `widerruf` — тоже Danke, текст из Figma), ошибка — серверную HTML-страницу
   в стиле Figma (charcoal/yellow, Anton/Inter из `/fonts/`) со сводкой ошибок, ссылками на поля и уже введёнными
   значениями, экранированными `htmlspecialchars`.
5. **Ретеншен**: при каждой успешной записи и в `submissions.php purge` удаляются строки старше `RETENTION_DAYS` и
   записи rate limit старше 24 часов. Отдельный cron не нужен; на хостинге его можно добавить (описано в README).
6. **Защита хранилища**: `storage/` с `.htaccess` (`Require all denied`) и `index.html`-заглушкой. В корневом `.htaccess`
   закрыты `server/`, `storage/`, `*.sqlite`, `*.log`, `config.local.php`. Роутер локально отдаёт на эти пути 404.
   В README рекомендовано вынести `STORAGE_PATH` выше webroot, если хостинг это позволяет.

## Угрозы и меры (минимальная threat model)
| Угроза | Мера | Проверка |
|---|---|---|
| Спам и боты | honeypot, минимальное время, rate limit по хешу IP | PHP-тесты AC-05 |
| Header injection в письмах | `clean_line` удаляет CR/LF, тема кодируется в MIME, Reply-To только после валидации | PHP-тест с `\r\n` во входных данных |
| XSS на странице ошибок без JS | `htmlspecialchars` на все значения | PHP-тест с `<script>` |
| CSRF / чужие сайты постят форму | проверка Origin/Referer (без сессий и cookies) | PHP-тест с чужим Origin → 403 |
| Утечка БД, логов, конфигурации | `.htaccess` deny, роутер 404, `config.local.php` в `.gitignore`, путь хранилища настраивается | curl-проверка AC-10, `git ls-files` |
| SQL injection | только подготовленные выражения PDO | review + тест с кавычками |
| Избыточные PII (DSGVO) | хранятся только поля формы и `consent_at`, без IP, удаление через 90 дней | тест purge, KUNDENFRAGEN |
| Секреты SMTP | только в `config.local.php` или env, не в git и не в логах | `git grep`, review |
| Потеря письма | копия в SQLite, `mail_status`, CLI-экспорт | тест сбоя транспорта |

## Последствия
- (+) Работает на любом хостинге с PHP 8.1+ и `pdo_sqlite`. Транспорт почты меняется в конфигурации без правки кода.
- (+) Локально всё проверяется без отправки писем (`log`). SMTP проверяется против фейкового SMTP-сервера из тестов.
- (−) Нативный SMTP-клиент — собственный код. Его поведение на реальном сервере хостера не проверено (NOT RUN до выбора хостинга).
- (−) Без админки владелец видит заявки только в письмах и через CLI; на хостинге без SSH CLI недоступен.
- (−) Тексты Datenschutz не описывают хранение заявок. Это блокер **публикации**, но не разработки (KUNDENFRAGEN).

## Проверка и пересмотр
Пересмотреть при выборе хостинга (нет PHP или `pdo_sqlite` → новый ADR), при запросе админки или при изменении правового заключения о сроке хранения.
